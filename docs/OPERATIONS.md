# 运行与排错

[返回 README](../README.md)

## 先看哪里

打开对应 Actions 运行，先看 **Summary** 中的报告日期、生成模式、环节和发送状态。失败时再展开失败步骤的日志，或下载 **Artifacts → report-output**。

| 产物 | 用途 |
| --- | --- |
| `run_status.json` | 生成模式、当前／失败环节、模型与翻译失败原因、各阶段接口协议和发送状态 |
| `diagnostics.json` | 抓取、翻译、模型和质量检查的诊断信息 |
| `last_report.md`、`last_card.json` | 通过生成检查的日报与卡片；不代表已发送成功 |
| `quality_errors.json` | 内容质量检查的具体失败条件，存在错误时生成 |
| `raw_candidates.json`、`filtered_candidates.json`、`scored_candidates.json` | 原始、过滤及评分后的候选记录 |
| `final_selected.json` | 最终入选新闻，含原文链接 |
| `llm_selected.json` | 模型精选阶段的结果（若有），不一定等于总量裁剪后的最终入选结果 |
| `state.json` | 翻译、模型、价格快照缓存及最近一次成功发送记录 |

产物保留 14 天。失败发生较早时，部分文件可能尚未生成；优先结合步骤日志和 `run_status.json` 判断。单个信源失败会记入诊断，不一定阻止其他合格内容发送。

## 状态字段

`mode` 表示内容生成模式：

| 值 | 含义 |
| --- | --- |
| `normal` | 正常生成模式，是否送达需另看 `delivery` |
| `direct_translation` | 模型未完成加工，使用已确认成功的基础翻译与规则筛选，不附运营建议 |
| `failed` | 内容生成或程序运行失败 |

`delivery` 表示发送结果：

| 值 | 含义与处理 |
| --- | --- |
| `sent` | 飞书明确确认正式日报成功；若后续保存状态失败，仍需结合日志核对发送日期是否已记录 |
| `already_sent` | 状态中该报告日期已成功发送，本次跳过 |
| `preview_only` | 仅生成预览，没有发送消息 |
| `not_attempted` | 未尝试发送，例如生成失败、缺少 webhook 或失败预览 |
| `rejected` | 飞书返回业务拒绝，查看错误码并检查机器人设置 |
| `failed` | HTTP 请求失败，查看错误码并检查机器人及服务状态 |
| `unconfirmed` | 发送结果未确认，先核对群内消息，再决定补跑 |
| `failure_notice_sent` | 失败通知已发送，正式日报没有发送，Actions 仍为失败 |

进程被中断时，状态可能只记录到最后一个已保存的环节。`unconfirmed` 也可能是发送前保存的状态，应同时核对日志与群消息。

## 常见处理

### 没有当天的运行记录

先检查工作流是否已启用，再考虑 GitHub 调度延迟。公共仓库长期无活动时，定时工作流可能被自动停用；看到 **Enable workflow** 时需要重新启用。启用后不会自动补跑漏掉的日期。

需要当天发送时，可从 `main` 手动运行，保持 `dry_run = false`、`skip_if_already_sent = true`。查看 [GitHub 关于停用与启用工作流的说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows)。

### 日报标注“直接翻译版”

查看 `llm_failures` 中的环节和原因。模型配置包括仓库 Secrets 中的 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`：

| 错误 | 优先检查 |
| --- | --- |
| 配置不完整 | 三个模型字段是否齐全 |
| HTTP 401／403 | 密钥是否有效、是否具备访问权限 |
| HTTP 404 | 地址路径和模型名是否正确 |
| HTTP 429 | 额度、余额与限流 |
| HTTP 5xx／超时 | 模型服务是否可用 |
| 返回格式错误、缺少条目 | 服务／模型是否支持请求格式，返回内容是否完整 |

`llm_protocols` 记录各阶段成功使用的 `responses`、`chat`，或 `cache`（命中缓存）。`OPENAI_BASE_URL` 填完整 `/responses` 地址可优先使用 Responses；填完整 `/chat/completions` 地址则优先使用 Chat。接口不存在或不支持方法时才尝试另一种，模型不存在、认证失败、限流和服务异常需处理实际原因。更换服务地址或首选协议会隔离原有模型缓存。

直译版已成功发送时，也会记录该报告日期。修好模型后若要再发完整版本，应先确认需要重复发送，再关闭跳过选项。

### 模型和基础翻译都失败

正式日报会停止，程序尝试发送一条含简短原因与运行链接的失败通知。查看 `llm_failures`、`translation_failures` 和诊断文件。

配置了 `DEEPL_API_KEY` 时使用 DeepL；否则使用 Google 非官方翻译接口。只有最终入选新闻的标题及存在的独立摘要都确认翻译成功，才允许发送直译版。翻译失败后返回的原文、旧失败缓存和中文模板都不视为成功译文。

### Actions 失败，群里却有消息

先确认群里收到的是正式日报还是失败通知。若是正式日报，也可能是飞书已接受消息，但回执丢失，或后续保存状态／归档产物失败。程序不会自动重试 POST，补跑前先核对，避免重复发送。

## 补跑与防重复限制

正常补跑保留 `skip_if_already_sent = true`。只有明确需要重复发送，才设为 `false`。`report_date` 是筛选日期，不是读取历史存档；历史新闻可能已从当前 RSS 中移除。

防重复依赖 `data/state.json` 中的 `delivery.last_sent_date`，并非永久发送台账：

- Actions 通过缓存恢复状态；缓存缺失或未保存时，无法确认之前是否成功发送。
- 状态只保存最近一次成功发送日期。补发其他日期会覆盖它，因此之后重跑较早已发送的日期仍可能重复。
- `concurrency` 让同一工作流串行运行；跨设备本地运行不共享这份缓存。

预览不发送任何群消息，也不更新成功发送日期。Actions 不保存预览状态缓存；本地预览则会更新本地翻译、模型和价格缓存。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 正常／直译版完成，或已发送而跳过；实际发送结果看 `delivery` |
| `1` | 程序异常 |
| `2` | 缺少飞书 webhook |
| `3` | 飞书失败或发送结果未确认 |
| `4` | 内容质量检查失败 |
| `5` | 模型不可用，且入选新闻的基础翻译未成功 |

预览模式同样执行生成质量检查，可能返回非零退出码。
